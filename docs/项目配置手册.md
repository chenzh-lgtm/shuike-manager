### 2.1 MySQL 数据库

#### 安装与启动

```bash
# 启动 MySQL
brew services start mysql@8.0
# 或
mysql.server start

# 首次登录并修改密码
mysql -u root
ALTER USER 'root'@'localhost' IDENTIFIED BY 'your_password';
FLUSH PRIVILEGES;
```

#### 创建数据库并导入表结构

```bash
# 方式一：执行 SQL 脚本（推荐）
mysql -u root -p < docs/database.sql

# 方式二：手动登录后执行
mysql -u root -p
source /path/to/docs/database.sql;
```

执行后会自动：
- 创建 `shuike_manager` 数据库
- 创建 19 张业务表
- 导入初始数据（学院、学期、用户、课程、系统配置等）

#### 验证

```sql
USE shuike_manager;
SHOW TABLES;
-- 应看到 19 张表

SELECT username, real_name FROM users;
-- 应看到 9 个初始用户，密码均为 123456
```

#### 连接信息（默认值）

| 参数 | 默认值 |
|------|--------|
| 地址 | localhost:3306 |
| 数据库 | shuike_manager |
| 用户名 | root |
| 密码 | root |

> 可在 `application.yml` 或通过环境变量 `DB_USERNAME` / `DB_PASSWORD` 修改。

### 2.3 MinIO 文件存储

MinIO 是一个开源的对象存储服务，兼容 Amazon S3 协议。本系统用它存储教师上传的授课计划附件、教学材料等文件。

#### 2.3.1 什么是 MinIO？为什么需要它？

| 概念 | 说明 |
|------|------|
| **类比** | MinIO 相当于"自建的阿里云 OSS / 亚马逊 S3" |
| **作用** | 存储用户上传的文件（Word、PDF、图片等） |
| **数据流** | 前端上传文件 → 后端接收 → 后端上传到 MinIO → 返回文件URL存数据库 |
| **与传统存储的区别** | 文件不存后端本地磁盘，而是存 MinIO，支持横向扩展、高可用 |

#### 2.3.2 安装 MinIO

##### macOS

```bash
# 方式一：Homebrew 安装（推荐）
brew install minio/stable/minio
brew install minio/stable/mc        # MinIO Client 命令行工具

# 方式二：直接下载二进制
curl -O https://dl.min.io/server/minio/release/darwin-amd64/minio
chmod +x minio
sudo mv minio /usr/local/bin/

curl -O https://dl.min.io/client/mc/release/darwin-amd64/mc
chmod +x mc
sudo mv mc /usr/local/bin/
```

##### Linux (Ubuntu/Debian)

```bash
wget https://dl.min.io/server/minio/release/linux-amd64/minio
chmod +x minio
sudo mv minio /usr/local/bin/

wget https://dl.min.io/client/mc/release/linux-amd64/mc
chmod +x mc
sudo mv mc /usr/local/bin/
```

##### Windows

```bash
# PowerShell 下载
Invoke-WebRequest -Uri "https://dl.min.io/server/minio/release/windows-amd64/minio.exe" -OutFile "minio.exe"
```

#### 2.3.3 初次配置与启动

##### 第一步：创建数据存储目录

```bash
# MinIO 的所有文件都存在这个目录里
mkdir -p ~/minio/data
```

##### 第二步：设置访问凭证（可选但推荐）

```bash
# 如果不设置，MinIO 默认的用户名密码为 minioadmin/minioadmin
# 设置自定义凭证：
export MINIO_ROOT_USER="admin"
export MINIO_ROOT_PASSWORD="passsword123456"

# 建议写入 shell 配置文件，避免每次手动 export：
echo 'export MINIO_ROOT_USER="admin"' >> ~/.zshrc
echo 'export MINIO_ROOT_PASSWORD="passsword123456"' >> ~/.zshrc
source ~/.zshrc
```

##### 第三步：启动 MinIO 服务

```bash
# 前台启动（方便查看日志）
minio server ~/minio/data \
  --console-address ":9001" \
  --address ":9000"

# 后台启动
nohup minio server ~/minio/data \
  --console-address ":9001" \
  --address ":9000" > ~/minio/minio.log 2>&1 &

# 设置开机自启（macOS brew 方式）
brew services start minio/stable/minio
```

##### 端口说明

| 端口 | 用途 | 访问方式 |
|------|------|----------|
| `9000` | **API 端口** | 后端代码通过这个端口上传/下载文件 |
| `9001` | **Web 控制台端口** | 浏览器访问管理界面 |

##### 启动成功标志

```
# 终端输出类似：
API: http://192.168.1.100:9000  http://127.0.0.1:9000
WebUI: http://192.168.1.100:9001 http://127.0.0.1:9001

# 表示 MinIO 已成功启动
```

#### 2.3.4 创建存储桶（Bucket）

MinIO 中的 Bucket 相当于"文件夹"，所有文件必须存在某个 Bucket 中。

##### 方式一：通过 Web 控制台创建（推荐新手）

```
1. 浏览器访问 http://localhost:9001
2. 输入用户名密码登录（默认 minioadmin / minioadmin）
3. 左侧菜单点击 "Buckets"
4. 点击 "Create Bucket"
5. Bucket Name 输入: shuike-manager
6. 点击 "Create Bucket"
```

##### 方式二：通过 MinIO Client (mc) 命令行创建

```bash
# 1. 配置 MinIO 连接别名
mc alias set myminio http://localhost:9000 minioadmin minioadmin
# 如果设置了自定义凭证：
mc alias set myminio http://localhost:9000 admin your_secure_password_123

# 2. 创建 bucket
mc mb myminio/shuike-manager

# 3. 验证 bucket 是否创建成功
mc ls myminio/
# 输出: [2026-06-08 12:00:00 CST]     0B shuike-manager/
```

#### 2.3.5 配置 Bucket 访问策略

文件上传到 MinIO 后，前端需要能访问。有两种方式：

##### 方式一：私有 Bucket + 预签名 URL（推荐，系统默认方案）

Bucket 保持私有，后端通过 MinIO SDK 生成**临时访问链接**给前端。

```bash
# Bucket 保持默认私有策略即可，无需额外配置
# 后端 Java 代码自动生成预签名 URL，有效期默认 10 分钟
```

> ✅ **优点**：安全，文件不会公开暴露
> ⚠️ 当前代码中 `FileController.java` 暂未实现预签名 URL（使用本地路径替代），后续迭代需要补充

##### 方式二：公开 Bucket（仅开发环境使用）

```bash
# 设置 bucket 为公开可读（仅开发环境！）
mc anonymous set download myminio/shuike-manager

# 恢复为私有
mc anonymous set private myminio/shuike-manager
```

或者通过 Web 控制台：
```
1. 进入 Bucket → shuike-manager
2. 点击 "Access Policy" → 选择 "Public"
3. 保存
```

#### 2.3.6 在系统中配置 MinIO 连接

编辑 `backend/src/main/resources/application.yml`：

```yaml
minio:
  endpoint: ${MINIO_ENDPOINT:http://localhost:9000}
  access-key: ${MINIO_ACCESS_KEY:minioadmin}
  secret-key: ${MINIO_SECRET_KEY:minioadmin}
  bucket: shuike-manager
```

##### 配置映射关系

| 配置项 | 对应 MinIO 中的概念 | 你的值 |
|--------|-------------------|--------|
| `endpoint` | MinIO API 地址 | `http://localhost:9000` |
| `access-key` | 登录用户名（RootUser） | `minioadmin` |
| `secret-key` | 登录密码（RootPass） | `minioadmin` |
| `bucket` | 存储桶名称 | `shuike-manager` |

##### 如果你设置了自定义凭证

假设你设置的是 `admin` / `mypassword123`，则通过环境变量配置：

```bash
export MINIO_ENDPOINT="http://localhost:9000"
export MINIO_ACCESS_KEY="admin"
export MINIO_SECRET_KEY="mypassword123"
```

#### 2.3.7 文件存储结构说明

系统上传的文件在 MinIO 中按以下目录结构组织：

```
├── teaching-plans/                # 授课计划附件
│   └── 2026/06/uuid-xxx.doc
├── phase-materials/               # 阶段性材料附件
│   └── 2026/06/uuid-xxx.pdf

```

> 路径格式：`{文件类型}/{年}/{月}/{UUID}.{扩展名}`

#### 2.3.9 常见问题

**Q: 启动 MinIO 报错 "Unable to read 'config.json'"**
```
原因：权限不足或数据目录不存在
解决：mkdir -p ~/minio/data && chmod 755 ~/minio/data
```

**Q: 上传文件报 "The specified bucket does not exist"**
```
原因：未创建 shuike-manager bucket
解决：参考 2.3.4 节创建 bucket
```

**Q: 文件能上传但前端无法访问/下载**
```
原因：Bucket 为私有且未使用预签名 URL
解决：设置 bucket 为公开（开发环境）或实现预签名 URL（生产环境）
```

**Q: 如何完全重置 MinIO？**
```bash
# 停止 MinIO 服务
# 清空数据目录
rm -rf ~/minio/data/*
# 重新启动 MinIO
minio server ~/minio/data --console-address ":9001"
```

#### 2.3.10 替换为阿里云 OSS（可选）

如果不方便部署 MinIO，也可以改用阿里云 OSS（对象存储服务）：

1. 开通 [阿里云 OSS](https://oss.console.aliyun.com/)，创建 Bucket
2. 获取 AccessKey ID 和 AccessKey Secret
3. 修改 `application.yml` 中 minio 相关配置指向 OSS
4. 或者保持 MinIO 配置不变，直接用环境变量指向阿里云 OSS 兼容端点（OSS 支持 S3 协议）

> 💡 **建议**：开发阶段直接用 MinIO 即可，免费且本机运行，无需注册云服务。上线后再根据学校 IT 环境决定是否迁移到 OSS 或其他存储方案。

### 2.4 火山引擎大模型 API

本项目使用火山引擎大模型进行 AI 评审、产业需求分析和对齐分析。

#### 获取 API KEY

1. 访问 [火山引擎控制台](https://console.volcengine.com/)
2. 开通「豆包大模型」或「DeepSeek」推理服务
3. 进入「API KEY 管理」→ 创建 API KEY
4. 复制生成的 KEY

#### 配置方式

```bash
# 方式一：环境变量（推荐，生产环境使用）
export VOLCANO_API_KEY="sk-xxxxxxxxxxxxxxxxxxxx"
export VOLCANO_ENDPOINT="https://ark.cn-beijing.volces.com/api/v3"   # 可选
```

**方式二**：直接编辑 `backend/src/main/resources/application.yml`：
```yaml
volcano:
  api-key: "sk-xxxxxxxxxxxxxxxxxxxx"   # 直接写入（仅开发环境）
```

#### 连接信息

| 参数 | 默认值 | 说明 |
|------|--------|------|
| API KEY | 空（必填） | 火山引擎 API KEY |
| Endpoint | https://ark.cn-beijing.volces.com/api/v3 | API 地址 |
| 默认模型 | doubao-pro-32k | 可换为 deepseek-chat 等 |
| Temperature | 0.3 | 输出随机性（0-1） |

> ⚠️ **重要**：当前 `AiEvaluationService.java` 中的 AI 调用为**模拟实现**（直接返回固定评分数据）。接入真实 API 时，需要完成 `VolcanoEngineClient.java` 的 SDK 调用逻辑。详见 [后端设计.md](后端设计.md) 第 6 节。

Nginx 配置示例：

```nginx
server {
    listen 80;
    server_name your-domain.com;

    # 前端静态资源

        root /path/to/frontend/dist;
        index index.html;
        try_files $uri $uri/ /index.html;

    # API 代理到后端
    location /api/ {
        proxy_pass http://localhost:8080;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
    }
}
```

## 7. 常见问题排查

### 7.1 后端启动报错 "Communications link failure"

```
原因：MySQL 未启动或连接信息不正确
解决：
  1. 确认 MySQL 正在运行: mysql.server status
  2. 检查 application.yml 中数据库连接信息
  3. 确认数据库 shuike_manager 已创建
```

### 7.2 后端启动报错 "Unable to connect to Redis"

```
原因：Redis 未启动
解决：
  1. 启动 Redis: redis-server 或 brew services start redis
  2. 如果 Redis 设置了密码，配置 REDIS_PASSWORD 环境变量
```

### 7.3 文件上传失败

```
原因：MinIO 未启动或配置不正确
解决：
  1. 确认 MinIO 正在运行: minio server ~/minio/data --console-address ":9001"
  2. 确认已创建 bucket: shuike-manager
  3. 检查 MINIO_ACCESS_KEY / MINIO_SECRET_KEY 与 MinIO 实际配置一致
```

### 7.4 AI 评审功能无响应

```
原因：
  1. VOLCANO_API_KEY 未配置
  2. 火山引擎 SDK 调用代码尚未实现（当前为模拟实现）
说明：
  - 核心审核流程不依赖 AI 功能，可正常使用
  - AI 模块代码框架已完整，接入真实 API 只需补充 VolcanoEngineClient.java
```

### 7.5 前端启动报 "Cannot find module"

```
解决：
  cd frontend
  rm -rf node_modules package-lock.json
  npm install
```

### 7.6 前端页面空白或路由跳转异常

```
原因：可能后端未启动，API 请求失败
解决：
  1. 确认后端 8080 端口正常
  2. 打开浏览器 DevTools → Network 查看 API 请求是否 200
  3. 检查 vite.config.ts 代理配置 target 地址
```

### 7.7 端口冲突

```bash
# 修改后端端口（application.yml）
server:
  port: 8081    # 改为其他端口

# 同时修改前端代理目标（vite.config.ts）
proxy: {
  '/api': {
    target: 'http://localhost:8081'    # 同步修改
  }
}
```
