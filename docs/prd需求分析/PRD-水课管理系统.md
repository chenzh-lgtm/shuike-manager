# 水课管理系统 — 产品需求文档（PRD）

> **版本**: v1.1 | **日期**: 2026-06-08 | **状态**: 已更新

---

## 1. Executive Summary（执行摘要）

### 1.1 问题陈述

当前高校教学管理中存在三个核心痛点：

1. **审核流程碎片化**：授课计划、教学方案和考核要求的提交与审核流程依赖纸质或通用 OA 系统，缺乏教学场景专用闭环，导致审核周期长、状态不可追踪。
2. **人培方案与产业需求脱节**：专业人才培养方案与产业需求之间的对齐分析缺乏系统化工具支撑，依赖人工比对，效率低下且容易遗漏。
3. **教学材料评审效率低**：阶段性教学材料的质量评价缺乏统一标准与智能辅助，审核人员工作量大、反馈周期长，教师改进方向不明确。

### 1.2 解决方案

构建一套校级「授课计划与复盘管理系统」，实现以下核心能力：

- 教师上传教学材料 → 二级学院审核 → 教务处审核的**线上审核闭环**
- 内置人培方案与课程标准模块，结合**火山引擎大语言模型**分析产业需求并自动对齐
- 通过 LLM 对阶段性教学材料进行**智能评分与优化建议**，支持教务处人工复核确认（通过/驳回）
- 面向不同角色提供**专属工作台**，实现精准权限隔离

### 1.3 成功标准

| KPI | 目标值 | 衡量方式 |
|-----|--------|----------|
| 审核流转效率 | 单次审核平均耗时从 3 天降至 1 天以内 | 系统操作日志时间戳统计 |
| 人培方案对齐覆盖率 | 100% 的课程计划与人培方案完成自动化对齐分析 | 系统对齐报告生成率 |
| AI 评分采纳率 | 教务处对 AI 评分的直接采纳率 ≥ 70% | 人工审核操作日志（通过数/总审核数） |
| 用户满意度 | 教师、二级学院负责人审核员、教务处三方 SUS 评分 ≥ 75 | 上线后 1 个月用户调研 |
| 系统可用性 | 核心功能可用率 ≥ 99.5% | 运维监控 |

## 2. User Experience & Functionality（用户体验与功能）

### 2.1 用户角色画像

| 角色 | 编码 | 描述 | 核心诉求 |
|------|------|------|----------|
| **教师** | TEACHER | 校内一线授课教师 | 上传授课计划/教学方案/考核要求，跟踪审核状态，获取 AI 反馈，查看产业需求对齐分析报告 |
| **二级学院负责人审核员** | COLLEGE_REVIEWER | 各学院教学秘书或教学副院长 | 审核本院教师提交的材料，加注意见后提交教务处 |
| **教务处** | OFFICE | 教务处工作人员（兼系统管理） | 校级终审、AI 评审复核、用户与权限管理、系统参数配置、数据归档 |
| **院长/专业负责人** | DEAN | 各学院院长或专业带头人 | 上传维护专业人才培养方案与课程标准，发起产业需求对齐分析 |
| **AI 评估引擎** | AI_ENGINE | 火山引擎大语言模型（系统组件） | 对阶段性教学材料进行智能评分、生成优化建议、分析产业需求与人培对齐 |

### 2.2 模块 A：授课计划上传与审核

#### US-A1：教师提交授课计划

> 作为一名**教师**，我希望通过系统上传授课计划（含 Word/PDF 附件），填写课程基本信息（课程名称、代码、学时、授课班级等），并提交至二级学院审核，以便规范化管理教学文件。

**验收标准**：
- 支持上传 Word（.doc/.docx）和 PDF 格式附件，单文件 ≤ 20MB
- 表单字段包括：课程名称、课程代码、授课学期、总学时、理论/实践学时、授课班级、教材信息
- 提交后状态变为「待学院审核」，教师可看到实时状态
- 提交后若未被审核，教师可撤回修改
- 重复提交同一课程计划时系统给出冲突提醒

#### US-A2：二级学院负责人审核

> 作为一名**二级学院负责人审核员**，我希望能查看本院所有教师提交的授课计划，逐一审核并提出意见，选择「通过」提交至教务处或「驳回」退回给教师修改，以便履行学院层面的质量把关职责。

**验收标准**：
- 审核列表支持按学期、教师、课程名称筛选
- 审核详情页展示教师提交的所有附件和填写信息
- 「通过」操作：填写审核意见（可选）→ 状态变为「待教务处审核」
- 「驳回」操作：必须填写驳回理由 → 状态变为「待修改」，教师收到通知
- 支持批量审核（勾选通过）

#### US-A3：教务处终审

> 作为一名**教务处**工作人员，我希望能对学院审核通过的教学计划进行终审，确认通过后归档，或驳回至学院/教师，以便实现校级的教学质量统一把控。

**验收标准**：
- 审核列表展示所有学院审核通过的材料
- 审核详情页展示学院审核意见及原始材料
- 「通过」操作：材料归档，状态变为「已通过」
- 「驳回」操作：可选择驳回至二级学院负责人审核员或直接退回教师，必须填写理由
- 支持导出审核通过清单为 Excel

### 2.3 模块 B：人才培养方案与课程标准管理

#### US-B1：院长上传人培方案

> 作为一名**院长/专业负责人**，我希望能上传专业人才培养方案和课程标准文件（Word/PDF），维护课程与培养目标的映射关系，以便系统进行产业需求对齐分析。

**验收标准**：
- 支持上传人培方案和课程标准文件（Word/PDF）
- 支持按专业、年级、学期维度组织管理
- 支持在线编辑培养目标、毕业要求、课程体系等结构化字段
- 支持课程的培养目标指标点映射矩阵录入

#### US-B2：产业需求对齐分析

> 作为一名**院长**，我希望系统能调用大语言模型，分析当前产业需求趋势（基于人培方案中的专业方向），并与现有培养目标和课程体系进行对齐分析，生成差距报告和改进建议。分析报告应对**教师**可见，方便教师在制定授课计划时参考产业需求方向。

**验收标准**：
- 院长发起分析后，LLM 自动生成分析报告
- 报告包含：产业需求关键词、人培方案覆盖度评分、未覆盖/弱覆盖的能力项、建议调整方向
- 报告支持 PDF 导出
- 分析结果保存至数据库，支持历史版本对比
- 教师可查看本院专业的对齐分析报告（只读权限）

### 2.4 模块 C：阶段性教学材料 AI 评审

#### US-C1：教师提交材料获取 AI 评审

> 作为一名**教师**，我希望能提交阶段性教学材料（如教学进度表、教案、学生作业样本等），由系统调用 AI 进行自动评分和优化建议，以便在正式提交审核前获得改进方向。

**验收标准**：
- 支持多文件上传（Word/PDF/图片），单次最多 10 个文件
- 选择材料类型：教学进度表、教案、课件、考核方案、学生成果样本
- 提交后 30 秒内返回 AI 评分（百分制）和优化建议列表
- 评分包含多维度：内容完整性、与课程标准匹配度、格式规范性、创新性
- 建议以「问题描述 + 修改方向」结构化呈现

#### US-C2：教务处复核 AI 评审结果

> 作为一名**教务处**工作人员，我希望能查看所有 AI 评审记录，对 AI 的评分和建议进行人工复核，选择「确认通过」或「驳回修改」，并在驳回时指定修改要求，以便保证评审质量的准确性和公正性。

**验收标准**：
- 审核列表支持按教师、材料类型、AI 评分区间、状态筛选
- 详情页展示原始材料、AI 评分详情、AI 优化建议
- 「确认通过」：记录教务处确认，AI 评分生效，材料状态更新
- 「驳回修改」：必须填写修改要求和截止日期，教师收到通知
- 支持教务处修改 AI 评分并注明理由
- 操作日志完整可追溯（谁、何时、做了什么操作）

### 2.5 模块 D：多角色门户与权限

#### US-D1：角色专属工作台

> 作为一名**系统用户**，我希望登录后看到与我角色匹配的专属工作台，包含待办事项、快捷入口和通知中心，以便高效完成工作。

**验收标准**：
- 不同角色登录后看到不同的仪表盘和导航菜单
- 教师工作台：我的课程、待修改材料、审核状态追踪、AI 评审入口、对齐分析报告
- 二级学院负责人审核员工作台：待审核列表、本院统计概览、审核历史
- 教务处工作台：全校待审核列表、各学院统计、审核历史、AI 评审复核、用户管理、系统配置
- 院长工作台：人培方案管理、对齐分析报告、本院统计总览
- 顶部通知铃铛：实时显示待办数量和最新通知

#### US-D2：用户与权限管理

> 作为一名**教务处**工作人员，我希望能管理用户账号、分配角色、配置审核流程节点，以便系统灵活适配不同学校的组织架构。

**验收标准**：
- 支持增删改查用户，关联学院/部门
- 支持一人多角色
- 支持配置审核流程（如是否启用学院审核环节）
- 支持学期数据归档和重置

### 2.6 非目标（Non-Goals）

以下功能**不在** MVP 范围内：

- ❌ 移动端原生 App（MVP 仅保障桌面端 + 响应式适配移动浏览器）

- ❌ 教师教学工作量自动核算
- ❌ 学情分析与成绩管理

## 3. AI 智能评审系统详细设计（核心功能）

> 本章节是系统的核心差异化功能，请仔细阅读。

### 3.1 功能概述

AI 智能评审系统是本项目的核心功能模块，通过调用火山引擎大语言模型（豆包/DeepSeek），实现对教师提交的阶段性教学材料进行**自动评分、多维度分析、优化建议生成**，并支持教务处进行**人工复核**，形成"AI初审 + 人工终审"的双重保障机制。

### 3.2 业务流程

```
教师上传材料 → 选择材料类型+关联课程
    │
    ▼
后端解析文档文本内容（PDF/Word 文本提取）
    │
    ▼
构建 Prompt（从数据库 ai_prompt_templates 表加载模板）
    │
    ▼
调用火山引擎大模型 API（HTTP POST JSON）
    │
    ▼
解析 LLM 返回的 JSON 结果 → 存入 ai_evaluations 表
    │
    ▼
状态更新：AI_COMPLETED，通知教师
    │
    ▼
【教师端】查看 AI 评分详情（综合分+4维度+建议列表）
    │
    ▼
【教务处】复核 AI 评审结果
    ├── 确认通过（评分生效，材料归档）
    └── 驳回修改（填写修改要求+截止日期，通知教师）
```

### 3.3 模型与工具要求

| 项目 | 说明 |
|------|------|
| **模型供应商** | 火山引擎方舟平台 (Ark) |
| **API 端点** | `https://ark.cn-beijing.volces.com/api/v3/chat/completions` |
| **默认模型** | 推理接入点 ID（如 `ep-20260502165153-5zwf7`，支持豆包/DeepSeek） |
| **调用方式** | HTTP POST + JSON，使用 RestTemplate 直接调用 |
| **认证方式** | `Authorization: Bearer {api-key}` |

### 3.4 AI 评审的四维评分体系

| 评审维度 | 权重 | 说明 | 输出格式 |
|----------|------|------|----------|
| **内容完整性** | 30% | 是否涵盖课程核心知识点、教学目标是否明确、教学环节是否完整 | 0-100 分 + 具体问题描述 |
| **与课程标准匹配度** | 30% | 教学内容是否与课程标准要求一致、知识点覆盖是否全面 | 0-100 分 + 具体问题描述 |
| **格式规范性** | 20% | 文档排版、引用规范、附件完整性、图表清晰度 | 0-100 分 + 具体问题描述 |
| **创新性** | 20% | 教学方法创新、案例新颖度、实践环节设计、新技术应用 | 0-100 分 + 具体问题描述 |

每个维度独立调用一次 LLM（4 次并发调用），加权计算总分，同时生成 3-5 条结构化优化建议。

### 3.5 Prompt 管理策略

- 所有 Prompt 模板存储于 `ai_prompt_templates` 表，按场景和维度区分
- 每个评审维度使用独立的 Prompt 模板，支持单独调优
- Prompt 版本化管理：每次修改创建新版本，支持回滚
- Prompt 变量替换：
  - `{{materialType}}` — 材料类型名称（如"教学进度表"）
  - `{{materialContent}}` — 文档解析后的文本内容
  - `{{courseStandard}}` — 关联课程标准内容

### 3.6 LLM 请求/响应格式

**请求示例**：
```json
POST /api/v3/chat/completions
{
  "model": "ep-20260502165153-5zwf7",
  "messages": [
    {"role": "system", "content": "你是一位资深教学评审专家..."},
    {"role": "user", "content": "## 教学材料内容\n{text}\n\n## 对应课程标准\n{standard}\n\n请评审"}
  ],
  "temperature": 0.3,
  "max_tokens": 2000
}
```

**要求 LLM 返回的 JSON 格式**：
```json
{
  "overall_score": 85,
  "dimension_scores": {
    "completeness": 90,
    "standardMatch": 82,
    "format": 88,
    "innovation": 80
  },
  "suggestions": [
    {"issue": "第三章缺少案例支撑", "direction": "建议增加2-3个实际教学案例"},
    {"issue": "考核标准不够具体", "direction": "建议细化到知识点级别"}
  ],
  "summary": "整体质量良好，教学内容完整，建议在实践环节加强"
}
```

### 3.7 评估策略与质量标准

| 维度 | 评估方法 | 通过标准 |
|------|----------|----------|
| **评分一致性** | 取 50 份材料，由 3 位教学专家分别评分取均值作为 Ground Truth，对比 AI 评分 | AI 评分与专家均值偏差 ≤ ±8 分 |
| **建议可用性** | 教务处在实际工作中对每条 AI 建议标记「采纳/部分采纳/不采纳」 | 采纳率（含部分采纳）≥ 70% |
| **响应时间** | 在典型负载下测量 AI 接口端到端延迟（4 个维度并发调用） | P95 ≤ 30 秒 |
| **安全性** | 送往火山引擎的文本需脱敏处理，移除教师个人信息 | 100% 脱敏 |
| **JSON 解析成功率** | LLM 返回的 JSON 可被程序正确解析 | ≥ 98% |

### 4.5 安全与隐私

- **认证**：JWT Token 过期时间 2 小时，支持 Refresh Token 续期
- **授权**：基于 RBAC 的接口级权限控制，后端每个 API 需声明 `@PreAuthorize`
- **数据隔离**：二级学院负责人审核员只能查看本院数据；教师只能查看自己的材料
- **文件安全**：上传文件类型白名单（.doc/.docx/.pdf/.jpg/.png），服务端病毒扫描（可选）
- **AI 数据安全**：送往火山引擎的文本需脱敏处理，移除教师/学生的个人身份信息（姓名替换为匿名 ID）
- **操作审计**：所有审核、评分、用户操作记录完整操作日志，保留 3 年
- **传输加密**：全站 HTTPS，API 通信强制 TLS 1.2+

### 5.2 技术风险与缓解措施

| 风险 | 影响 | 概率 | 缓解措施 |
|------|------|------|----------|
| **LLM 输出不稳定**：同一材料两次评分差异过大 | 用户信任度下降 | 中 | 设置 temperature ≤ 0.3；对同一材料缓存首次评分结果；教务处可人工修正 |
| **文档解析准确率不足**：Word/PDF 中包含复杂表格、图片时文本提取质量差 | AI 评审质量下降 | 高 | 要求教师同步填写结构化字段；PDF 使用 PDFBox 的表格提取增强能力；后续迭代增加 OCR 模块 |
| **审核流程变化**：不同学校/学期审核流程可能不同 | 系统灵活性不足 | 中 | 审核流程配置化：流程节点和审批人关系存于配置表，教务处可在线调整 |
| **文件存储成本**：大量附件长期积累导致存储成本上升 | 运维成本增加 | 低 | 设置附件保留策略（如毕业后 1 年自动归档）；MinIO 支持压缩和生命周期管理 |
| **火山引擎 API 不可用** | 服务中断 | 低 | 实现熔断机制（Resilience4j）；AI 评审失败时提示用户稍后重试，不阻塞人工审核流程 |
| **并发压力**：期末集中提交导致系统负载高峰 | 响应变慢 | 中 | 文件上传异步化；AI 评审改为异步队列处理；数据库读写分离（v1.1+） |

## 附录 C：AI 评审维度详细说明

教学材料 AI 评审采用四维度打分体系，每个维度独立调用大模型进行评分：

| 评审维度 | 权重 | 满分 | 优秀(≥90) | 良好(≥75) | 合格(≥60) | 待改进(<60) |
|----------|------|------|-----------|-----------|-----------|-------------|
| 内容完整性 | 30% | 100 | 知识点全覆盖，教学目标清晰 | 主要知识点已覆盖 | 基本框架完整 | 存在重大遗漏 |
| 与课程标准匹配度 | 30% | 100 | 完美对齐课程标准 | 大部分对齐 | 基本对齐 | 严重偏离 |
| 格式规范性 | 20% | 100 | 排版美观，引用规范 | 格式整齐 | 基本可读 | 格式混乱 |
| 创新性 | 20% | 100 | 教学方法有突破性创新 | 有一定新颖设计 | 传统方法为主 | 照本宣科 |

**总分计算**：加权求和后取整。总分 ≥90 为优秀，≥75 为良好，≥60 为合格，<60 为待改进。

**建议生成规则**：评分低于 75 的维度必须生成至少 1 条针对性优化建议，每条建议包含「问题描述」+「修改方向」。
