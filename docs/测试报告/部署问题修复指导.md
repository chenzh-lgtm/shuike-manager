## 2. 根因分析

### 2.1 数据库 schema 版本不一致

```
本地开发环境 (MySQL 8.0 via Docker)     ECS 生产环境 (MySQL 5.6 原生)
┌─────────────────────────────┐         ┌──────────────────────────────┐
│ docs/数据库/database-v2.0.sql │         │ docs/database.sql (v1.0)       │
│ alignment_reports 含:        │         │ alignment_reports 缺少:        │
│   + report_json LONGTEXT     │   ≠    │   ✗ report_json               │
│   + dimension_scores TEXT    │         │                                │
│   + industry_keywords TEXT   │         │                                │
└─────────────────────────────┘         └──────────────────────────────┘
```

**ECS 日志关键证据**:

```
[对齐分析] LLM返回成功, 耗时=121678ms, 响应长度=5974
[对齐分析] JSON解析失败:
Cause: java.sql.SQLSyntaxErrorException: Unknown column 'report_json' in 'field list'
```

LLM 分析本身成功（耗时 2 分钟、返回 5974 字符），但 INSERT 时因 `report_json` 列不存在而失败。

### 2.2 异步线程丢失 SecurityContext

Spring Security 的 `SecurityContextHolder` 默认使用 `ThreadLocal` 存储认证信息。`@Async("aiEvaluationExecutor")` 方法在线程池的独立线程中执行，不会自动继承 HTTP 请求线程的 SecurityContext。

```java
// ❌ 错误做法：异步方法中直接调用 SecurityUtils
@Async("aiEvaluationExecutor")
public void analyzeAsync(Long tcpId) {
    Long userId = SecurityUtils.getCurrentUserId(); // → 始终为 null
}

// ✅ 正确做法：Controller 提前取出 userId，显式传参
@PostMapping("/analyze")
public ApiResponse<String> analyze(@RequestBody Map<String, Long> body) {
    Long userId = SecurityUtils.getCurrentUserId(); // HTTP 线程中获取
    service.analyzeAsync(tcpId, userId);            // 显式传入
}
```

### 2.3 Mac ARM64 → AMD64 构建性能

| 构建方式 | 耗时 | 原因 |
|----------|:--:|------|
| 本地 `docker build --platform linux/amd64` | 2-3 小时 | QEMU 用户态模拟 Java 编译（每字节码指令翻译 1 条→50+ 条 ARM 指令） |
| ECS `docker build` (原生 x86_64) | 8-15 分钟 | 原生执行，但需从 Docker Hub 拉取镜像（国内限速） |
| **本地 `mvn package` + ECS 替换 JAR** ✅ | **1-2 分钟** | 跳过模拟，直接替换运行容器 JAR |

## 3. 修复方案

### 3.1 数据库补列（已修复）

```sql
-- 在 ECS MySQL 上执行
ALTER TABLE shuike_manager.alignment_reports 
ADD COLUMN report_json LONGTEXT DEFAULT NULL 
COMMENT 'v2.0完整分析报告JSON' AFTER suggestions;
```

验证：
```sql
DESCRIBE shuike_manager.alignment_reports;
-- 应包含 report_json (longtext) 列
```

### 3.2 后端代码修改（已修复）

修改文件：`backend/.../alignment/controller/AlignmentController.java`

```java
// 第 28-35 行，增加 userId 透传
@PostMapping("/analyze")
public ApiResponse<String> analyze(@RequestBody Map<String, Long> body) {
    Long tcpId = body.get("tcpId");
    if (tcpId == null) return ApiResponse.error(400, "请选择人培方案");
    Long userId = SecurityUtils.getCurrentUserId();  // ← 新增
    service.analyzeAsync(tcpId, userId);              // ← 传入 userId
    return ApiResponse.success("AI分析已启动，预计1-2分钟完成...");
}
```

修改文件：`backend/.../alignment/service/AlignmentService.java`

```java
// 异步入口增加 initiatorId 参数
@Async("aiEvaluationExecutor")
public void analyzeAsync(Long tcpId, Long initiatorId) { // ← 新增参数
    try {
        analyze(tcpId, initiatorId);                     // ← 透传
    } catch (Exception e) {
        log.error("[对齐分析] 异步执行失败: ...", e);     // ← 增加完整堆栈
    }
}

// analyze() 方法中原有的 SecurityUtils.getCurrentUserId() 替换为传入参数
report.setInitiatorId(initiatorId); // ← 直接使用传入的 initiatorId
```

### 3.3 通用规则：@Async + SecurityContext

**所有 `@Async` 方法如果需要当前用户信息，必须遵循此规范：**

```java
// Controller 层
@PostMapping("/xxx")
public ApiResponse<?> xxx() {
    Long userId = SecurityUtils.getCurrentUserId();  // HTTP 线程获取
    service.asyncMethod(userId, ...);                 // 显式传入
}

// Service 层
@Async("aiEvaluationExecutor")
public void asyncMethod(Long userId, ...) {
    // 直接使用 userId，不要调用 SecurityUtils
}
```

## 4. 快速部署流程（后端）

### 标准流程（推荐，总耗时 1-2 分钟）

```bash
# 步骤1：本地编译 JAR（30秒，ARM64 Mac 原生执行）
cd backend
export JAVA_HOME=/Library/Java/JavaVirtualMachines/jdk1.8.0_202.jdk/Contents/Home
mvn clean package -DskipTests -q

# 步骤2：上传 JAR 到 ECS 并替换容器（30秒）
scp target/teacher-file-manager-1.0.0.jar root@<ECS_IP>:/opt/shuike/backend/
ssh root@<ECS_IP> '
  docker cp /opt/shuike/backend/teacher-file-manager-1.0.0.jar shuike-backend:/app/app.jar
  docker restart shuike-backend
  sleep 15 && docker logs shuike-backend --tail 10  # 确认启动成功
'

# 步骤3（可选）：提交运行状态为镜像 + 推送 ACR（1分钟）
ssh root@<ECS_IP> '
  docker commit shuike-backend shuike-backend:1.0
  docker tag shuike-backend:1.0 \
    <ACR_REGISTRY>/shuike2026/teacher-file-manager-backend:1.0
  docker push <ACR_REGISTRY>/shuike2026/teacher-file-manager-backend:1.0
'
```

### 前端部署（不变，本地 `docker build` 即可）

前端 Node.js 编译不涉及 JDK/Maven 模拟，本地 `docker build --platform linux/amd64` 始终快速：

```bash
cd frontend
docker build --platform linux/amd64 -t shuike-frontend:1.0 .
docker tag shuike-frontend:1.0 <ACR_REGISTRY>/shuike2026/teacher-file-manager-frontend:1.0
docker push <ACR_REGISTRY>/shuike2026/teacher-file-manager-frontend:1.0
```

### 完整部署（前后端都改了的情况）

```bash
# 后端：本地 mvn → 上传 JAR → 替换容器
cd backend && mvn clean package -DskipTests -q
scp target/teacher-file-manager-1.0.0.jar root@<ECS_IP>:/opt/shuike/backend/
ssh root@<ECS_IP> 'docker cp /opt/shuike/backend/teacher-file-manager-1.0.0.jar shuike-backend:/app/app.jar && docker restart shuike-backend'

# 前端：本地 docker build → 推送 ACR → ECS 拉取重启
cd frontend && docker build --platform linux/amd64 -t shuike-frontend:1.0 .
docker push <ACR_REGISTRY>/shuike2026/teacher-file-manager-frontend:1.0
ssh root@<ECS_IP> 'cd /opt/shuike && docker compose pull frontend && docker compose up -d --no-deps frontend'
```

## 7. 经验教训

1. **Schema 版本管理**：每次数据表变更要用 `ALTER TABLE` 执行到 ECS 生产库，不能仅依赖 `docs/数据库/` 中的建表脚本（那些只在容器首次 `docker compose up` 时执行）
2. **异步方法安全上下文**：`@Async` 方法绝不能直接调用 `SecurityUtils`，必须在 Controller 层提前取出所需用户信息作为参数传入
3. **Mac ARM64 开发 Java 项目**：后端不要用 `docker build --platform linux/amd64`，改用**本地编译 JAR → scp 到 ECS 替换**的方式，效率提升 100 倍以上
4. **ECS Docker Hub 限流**：ECS 上 `docker pull` 基本镜像可能被限速（429 Too Many Requests），尽量复用已有镜像或提前缓存
