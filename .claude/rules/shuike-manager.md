# Shuike Manager - 项目级规则

> 水课管理系统开发规则，AI 在编写/修改/审查本项目代码时必须遵守。

---

## 1. 运行环境

- 本项目在 **macBook (macOS)** 上开发运行，**不是 Linux**
- 本地环境版本（开发时必须使用与这些版本兼容的代码和依赖）:

| 工具 | 版本 |
|------|------|
| Java | **1.8** (JDK 8) |
| Maven | **3.5.2** |
| npm | **11.12.1** |
| MySQL | **5.6.26** (生产环境) |
| Git | **2.37.1** |
| Node.js | **18.x** |

- 后端代码必须兼容 **Java 8**（不能使用 Java 9+ 特性如 `var`、`List.of()`、模块系统等）
- MySQL 兼容 **5.6** 语法（避免使用 5.7+ 特性如 `JSON` 列类型、窗口函数等）
- Maven 插件版本需兼容 3.5.x

## 2. 注释规范

- **代码必须使用中文注释**
- 所有类、方法、关键逻辑块都需要添加注释说明
- 注释格式：
  - 类级别：`/** 类功能描述 */`
  - 方法级别：`/** 方法功能说明 @param 参数说明 @return 返回值说明 */`
  - 复杂逻辑：行内注释说明为什么这么写
- 前端（Vue）同样使用中文注释

## 3. 环境检查原则

- 使用任何系统工具前（如 node、npm、maven、git），**先检查系统中是否已安装**
- 如果已安装则直接使用，**不要重复安装**
- 本电脑已有环境：node.js、npm、maven、git、java — 不要尝试安装这些工具

## 4. Git 提交控制

- **不要自动提交代码到 GitHub**
- 只有用户明确说出 **"提交"** 两个字时，才执行 `git commit` 和 `git push`
- 可以修改本地代码、文件，不在此限制内

## 5. 任务总结

- **每次完成任务后，必须列出本次做了哪些内容**
- 总结格式：用表格或编号列表说明所有改动点

## 6. 错误积累与自省

- 写同一个逻辑功能时，如果出错一次，**必须自己总结并记住错误原因**
- 下次再碰到同样类型的功能逻辑，**不能重复犯同样的错误**
- 发现错误后，要在回复中明确说明"本次错误原因：xxx，下次避免方式：xxx"

## 7. Bug 修复策略

- 当某个功能无法实现或代码出 bug 时，**不要直接删除该功能代码**
- 应该**换个思路重新实现**，保留功能完整性
- 多次尝试不同方案仍无法解决时，向用户说明情况并请求指导
