# 软件需求规格说明书 (SRS)

## 1. 引言

### 1.1 编写目的

本文档旨在明确"个人在线记账应用"的功能需求与非功能需求，为后续的概要设计、详细设计和编码测试提供依据。文档的预期读者包括：项目开发者、测试人员及项目评审人员。

### 1.2 项目范围

本项目构建一个基于 Web 的个人记账应用，主要范围包括：

- 用户注册与登录
- 收支记录的新增、编辑、删除、查询
- 月度收支汇总报表的生成与展示
- 收支分类管理

本项目不包含：多用户协作、预算管理、投资理财、银行账户同步、多币种支持、数据导入导出等功能（以上功能列入后续迭代计划）。

### 1.3 参考文献

- 《可行性研究报告》（本项目 Phase 1 产出）

## 2. 系统概述

### 2.1 系统总体描述

本系统是一个基于 B/S 架构的个人在线记账工具。用户通过浏览器访问 Web 页面，注册账号后即可记录日常收入与支出，系统按月份自动汇总收支数据并以图表和列表形式展示。

系统核心业务流：

1. 用户注册/登录
2. 用户新增一笔收入或支出记录（金额、分类、日期、备注）
3. 用户可查看所有记录列表，支持按月份筛选
4. 用户可编辑或删除已有记录
5. 系统自动汇总月度数据，生成报表（总额、分类占比、趋势）

### 2.2 用户角色定义

| 角色 | 描述 |
|------|------|
| 普通用户（User） | 已注册并登录的用户，可管理自己的收支记录和查看报表 |

### 2.3 运行环境

| 项目 | 要求 |
|------|------|
| 浏览器 | Chrome 90+, Firefox 88+, Safari 14+, Edge 90+ |
| 屏幕分辨率 | 最低 360px 宽（移动端），推荐 1280x720 以上（桌面端） |
| 网络 | 需网络连接访问服务端 |
| 服务端 | Node.js 18+, 操作系统 Linux/macOS/Windows |

## 3. 功能需求

### 3.1 用户注册（FR-01）

#### 3.1.1 描述
用户通过提供邮箱和密码创建账号。

#### 3.1.2 输入/输出
- **输入**：邮箱地址（字符串，符合邮箱格式）、密码（字符串，最少 6 位）
- **输出**：注册成功提示并跳转至登录页；或注册失败错误提示

#### 3.1.3 前置条件与后置条件
- **前置条件**：邮箱未被注册
- **后置条件**：用户账号创建成功，数据持久化到数据库

#### 3.1.4 优先级
**Must** — 核心功能，无注册无法区分用户数据

---

### 3.2 用户登录（FR-02）

#### 3.2.1 描述
已注册用户通过邮箱和密码登录系统，获取访问令牌。

#### 3.2.2 输入/输出
- **输入**：邮箱地址、密码
- **输出**：登录成功跳转至首页并存储 JWT 令牌；或登录失败错误提示

#### 3.2.3 前置条件与后置条件
- **前置条件**：邮箱已注册
- **后置条件**：用户获得有效 JWT 令牌，可访问受保护的 API

#### 3.2.4 优先级
**Must**

---

### 3.3 新增收支记录（FR-03）

#### 3.3.1 描述
用户记录一笔收入或支出，包含金额、类型、分类、日期、备注。

#### 3.3.2 输入/输出
- **输入**：
  - 类型（枚举：income / expense）
  - 金额（正数，最多两位小数）
  - 分类 ID（关联到分类表）
  - 日期（日期格式：YYYY-MM-DD，默认当天）
  - 备注（可选，最多 200 个字符）
- **输出**：新增成功的记录详情；或失败错误提示

#### 3.3.3 前置条件与后置条件
- **前置条件**：用户已登录
- **后置条件**：记录持久化到数据库

#### 3.3.4 优先级
**Must** — 核心功能

---

### 3.4 编辑收支记录（FR-04）

#### 3.4.1 描述
用户修改已有收支记录的金额、分类、日期或备注。

#### 3.4.2 输入/输出
- **输入**：记录 ID + 需修改的字段（金额、分类 ID、日期、备注）
- **输出**：更新成功的记录详情；或失败错误提示（如记录不存在、无权限）

#### 3.4.3 前置条件与后置条件
- **前置条件**：用户已登录，记录属于当前用户，记录存在
- **后置条件**：数据库中记录被更新

#### 3.4.4 优先级
**Must**

---

### 3.5 删除收支记录（FR-05）

#### 3.5.1 描述
用户删除一笔已有的收支记录。

#### 3.5.2 输入/输出
- **输入**：记录 ID
- **输出**：删除成功提示；或失败错误提示

#### 3.5.3 前置条件与后置条件
- **前置条件**：用户已登录，记录属于当前用户，记录存在
- **后置条件**：记录从数据库中删除（软删除或硬删除）

#### 3.5.4 优先级
**Must**

---

### 3.6 收支记录列表查询（FR-06）

#### 3.6.1 描述
用户查看自己的收支记录列表，支持按月份筛选和按类型筛选。

#### 3.6.2 输入/输出
- **输入**：
  - 月份筛选（可选，格式：YYYY-MM）
  - 类型筛选（可选，income / expense / all）
  - 分页参数（页码、每页条数）
- **输出**：记录列表（含总条数、总页数、当前页数据）

#### 3.6.3 前置条件与后置条件
- **前置条件**：用户已登录
- **后置条件**：无

#### 3.6.4 优先级
**Must**

---

### 3.7 月度收支汇总报表（FR-07）

#### 3.7.1 描述
系统自动汇总指定月份的收入总额、支出总额、结余，以及按分类汇总的支出/收入明细。

#### 3.7.2 输入/输出
- **输入**：月份（YYYY-MM）
- **输出**：
  - 月度总收入
  - 月度总支出
  - 月度结余（收入 - 支出）
  - 支出按分类汇总（分类名称、金额、占比）
  - 收入按分类汇总（分类名称、金额、占比）

#### 3.7.3 前置条件与后置条件
- **前置条件**：用户已登录
- **后置条件**：无

#### 3.7.4 优先级
**Must** — 核心差异化功能

---

### 3.8 分类管理（FR-08）

#### 3.8.1 描述
系统预置常用收支分类，用户可查看分类列表。

#### 3.8.2 输入/输出
- **输入**：无（查看），或类型筛选（income / expense）
- **输出**：分类列表（ID、名称、图标、类型）

#### 3.8.3 前置条件与后置条件
- **前置条件**：用户已登录
- **后置条件**：无

#### 3.8.4 优先级
**Should** — 使用预置分类可满足 MVP 需求

---

### 3.9 用户信息管理（FR-09）

#### 3.9.1 描述
用户可查看和修改自己的基本信息（昵称）。

#### 3.9.2 输入/输出
- **输入**：昵称（可选）
- **输出**：更新后的用户信息

#### 3.9.3 前置条件与后置条件
- **前置条件**：用户已登录
- **后置条件**：用户信息更新

#### 3.9.4 优先级
**Could** — 锦上添花功能

---

## 4. 非功能需求

### 4.1 性能需求

| 指标 | 要求 |
|------|------|
| 页面首次加载时间 | < 3 秒（3G 网络，含首屏渲染） |
| API 响应时间 | < 500ms（P95） |
| 并发用户数 | 支持 50 个并发用户（MVP 阶段） |
| 数据库查询 | 单用户全年记录查询 < 200ms |

### 4.2 安全需求

| 指标 | 要求 |
|------|------|
| 密码存储 | 使用 bcrypt（salt rounds >= 10）进行哈希 |
| 身份认证 | 使用 JWT（HS256），令牌有效期 7 天 |
| 数据传输 | 生产环境强制 HTTPS |
| 权限控制 | 用户只能访问和操作自己的数据 |
| SQL 注入防护 | 使用参数化查询或 ORM |
| XSS 防护 | 前端输出进行 HTML 转义，React 默认安全 |

### 4.3 可用性需求

| 指标 | 要求 |
|------|------|
| 响应式设计 | 适配手机端（360px+）和桌面端 |
| 操作反馈 | 所有操作（增删改）需有明确的成功/失败提示 |
| 表单验证 | 前端实时校验，提交前阻止无效数据 |
| 加载状态 | 数据加载中显示 Loading 指示器 |

### 4.4 可维护性需求

| 指标 | 要求 |
|------|------|
| 代码规范 | 前端使用 ESLint + Prettier，后端使用 ESLint |
| 注释 | 核心业务逻辑添加注释说明 |
| API 文档 | 接口提供 Swagger/OpenAPI 文档或在代码中清晰标注 |

### 4.5 兼容性需求

| 指标 | 要求 |
|------|------|
| 浏览器 | Chrome 90+, Firefox 88+, Safari 14+, Edge 90+ |
| 移动端 | iOS Safari 14+, Android Chrome 90+ |

## 5. 数据需求

### 5.1 数据实体概述

| 实体 | 描述 | 核心字段 |
|------|------|---------|
| User | 用户账号 | id, email, password_hash, nickname, created_at |
| Category | 收支分类 | id, name, type(income/expense), icon |
| Transaction | 收支记录 | id, user_id, category_id, type, amount, date, note, created_at, updated_at |

### 5.2 数据约束

- 金额必须为正数，保留两位小数
- 日期不能是未来日期（以记录创建时的服务端时间为准）
- 邮箱全局唯一（不区分大小写）
- 删除记录时，检查该记录归属是否为当前用户

## 6. 系统接口需求

### 6.1 用户界面需求

| 页面 | 描述 |
|------|------|
| 登录页 | 邮箱、密码输入，登录按钮，注册链接 |
| 注册页 | 邮箱、密码、确认密码输入，注册按钮 |
| 首页/仪表盘 | 当月收支概览卡片（收入、支出、结余），最近记录列表 |
| 记账页 | 新增收支记录表单（类型切换、金额、分类选择、日期、备注） |
| 记录列表页 | 收支记录列表，支持筛选、分页，每行可编辑/删除 |
| 月度报表页 | 月份选择器，月度汇总数据，分类饼图/柱状图 |
| 个人中心 | 昵称修改，退出登录 |

### 6.2 外部接口需求

本系统为独立运行的个人应用，不依赖外部第三方 API（如银行接口、支付接口等）。
