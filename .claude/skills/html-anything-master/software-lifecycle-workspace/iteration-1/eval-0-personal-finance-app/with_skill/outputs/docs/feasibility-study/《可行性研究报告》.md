# 可行性研究报告

## 1. 引言

### 1.1 项目背景

随着个人理财意识的增强，越来越多的人希望有一个便捷的工具来记录日常收支、掌握财务状况。当前市场上的记账应用（如随手记、挖财等）功能繁杂、广告众多，部分用户倾向于使用一个简洁、专注、自托管的在线记账工具。本项目旨在构建一个基于 Web 的个人记账应用，支持收入与支出记录，并自动生成月度财务报表。

### 1.2 项目目标

- 构建一个在线个人记账应用，用户可随时随地通过浏览器访问
- 支持收入与支出的分类记录与管理
- 自动生成月度收支汇总报表
- 采用 React + Node.js 技术栈，前后端分离架构
- 界面简洁直观，操作便捷

### 1.3 术语与缩写

| 术语/缩写 | 说明 |
|-----------|------|
| SPA | Single Page Application，单页应用 |
| REST | Representational State Transfer，表现层状态转换 |
| CRUD | Create, Read, Update, Delete |
| JWT | JSON Web Token，身份认证令牌 |
| MVP | Minimum Viable Product，最小可行产品 |
| ORM | Object-Relational Mapping，对象关系映射 |

## 2. 技术可行性

### 2.1 技术方案概述

本系统采用前后端分离的 B/S 架构：

- **前端（React）**：使用 React 18+ 构建 SPA，搭配 React Router 实现路由管理，使用 Axios 进行 HTTP 通信，使用 Recharts 或 Chart.js 实现图表可视化，使用 Tailwind CSS 或 Ant Design 实现 UI 组件。
- **后端（Node.js）**：使用 Express.js 或 Koa.js 框架构建 RESTful API，使用 Sequelize 或 Prisma 作为 ORM，使用 SQLite 或 PostgreSQL 作为数据库，采用 JWT 实现用户认证。
- **部署**：支持 Docker 容器化部署，可部署于云服务器或个人 NAS。

技术栈全面成熟，社区生态完善，文档丰富。React 和 Node.js 均为当前市场主流技术，拥有大量开发者和丰富的第三方库支持。

### 2.2 技术风险评估

| 风险项 | 风险等级 | 描述 | 缓解措施 |
|--------|---------|------|---------|
| 数据安全 | 中 | 用户财务数据为敏感信息，需防泄漏 | 采用 bcrypt 加密密码，JWT 认证，HTTPS 传输，数据加密存储 |
| 浏览器兼容性 | 低 | 不同浏览器可能存在渲染差异 | 使用主流浏览器测试，采用标准 CSS，Polyfill 保障兼容 |
| 性能瓶颈 | 低 | 单用户应用，数据量小，性能压力不大 | SQLite 对于个人用户足够；如数据量大可切换 PostgreSQL |
| 技术栈学习曲线 | 低 | React + Node.js 均为成熟技术 | 开发者为熟悉该技术栈的人员 |

### 2.3 技术可行性结论

**技术可行。** React + Node.js 技术栈完全成熟，所需功能（CRUD 记录、报表生成）均有成熟的库和方案支持。不存在不可克服的技术障碍。

## 3. 经济可行性

### 3.1 开发成本估算

本项目为个人/小团队项目，采用开源技术栈，无软件授权费用。

| 成本项 | 估算 |
|--------|------|
| 人力成本（1人全栈开发） | 约 40-60 人天 |
| 服务器/云服务费用 | 约 50-100 元/月（低配云服务器）或 0 元（自托管） |
| 域名费用 | 约 50 元/年 |
| 第三方服务费用 | 0 元（全部使用开源方案） |
| **总计** | **约 2-3 万元（首年，含人力估算）** |

### 3.2 预期收益分析

本项目定位为个人工具，不以盈利为主要目标。潜在收益包括：

- 满足自身及家庭的记账需求，提升财务管理效率
- 作为开源项目发布，获得社区关注与技术影响力
- 可作为技术作品展示，用于求职或个人品牌建设

### 3.3 成本效益分析

项目初始投入低，主要为开发者时间成本。个人财务管理效率的提升收益难以量化，但持续的记账习惯有助于理性消费和储蓄规划。项目具有正向的隐形成本效益比。

### 3.4 经济可行性结论

**经济可行。** 项目投入成本低，使用开源技术栈避免软件授权费用，完全在个人可承受范围内。

## 4. 法律可行性

### 4.1 法律法规遵从性

- **个人数据保护**：本项目面向自用或小范围使用，如涉及其他用户的个人财务数据，需遵守《中华人民共和国个人信息保护法》，明确告知数据收集范围与用途。
- **数据本地化**：建议将数据存储于境内服务器，避免跨境数据传输合规问题。
- **开源许可证**：所使用的第三方开源库均需遵循其各自许可证要求，本项目本身可采用 MIT 许可证开源。

### 4.2 知识产权分析

- 本应用核心代码为自主开发，不存在侵犯第三方知识产权风险。
- 所使用的 React、Node.js、Express.js、SQLite 等均为 MIT 许可证或同等宽松许可证，允许商业及个人使用。
- UI 设计需避免直接复制竞品界面，保持原创性。

### 4.3 法律可行性结论

**法律可行。** 作为个人工具类应用，法律风险较低。若对外提供服务，需关注个人信息保护法规。知识产权方面无实质性风险。

## 5. 操作可行性

### 5.1 组织影响分析

本项目为个人使用工具，不涉及组织层面的工作流程变更。用户（即开发者本人或家庭成员）只需通过浏览器访问即可使用，无需额外培训。

### 5.2 用户接受度分析

- **易用性**：Web 应用无需安装，打开浏览器即可使用，降低使用门槛
- **功能匹配度**：聚焦于记账核心功能，无冗余功能，减少学习成本
- **数据掌控**：用户数据存储在自有服务器上，增强数据安全感
- **移动端适配**：需实现响应式设计，确保手机端也能便捷使用

### 5.3 操作可行性结论

**操作可行。** 应用使用门槛低，无需安装部署即可访问（Web 端），用户可轻松上手。

## 7. 综合结论与建议

经过技术、经济、法律、操作、时间五个维度的综合评估，本项目**建议继续推进**。

**核心优势：**
- 技术栈成熟稳定，无技术障碍
- 开发成本低，经济负担小
- 法律风险可控
- 功能边界清晰，适合个人开发者完成

**建议：**
1. 首版本（MVP）聚焦核心功能：记账记录 + 月度报表，不贪多求全
2. 采用 SQLite 简化数据库部署和运维
3. 实现响应式设计，确保移动端可用
4. 后续可迭代增加预算管理、多币种支持、数据导入导出等功能
