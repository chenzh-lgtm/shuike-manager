# Phase 2: Requirements Analysis -- 图书管理系统需求分析

## 1. 引言

### 1.1 目的
本文档定义图书管理系统的功能需求和非功能需求，作为后续设计和开发的依据。

### 1.2 范围
系统涵盖图书管理、用户管理、借阅管理三大核心模块。

---

## 2. 功能性需求 (Functional Requirements)

### 2.1 图书管理模块 (Book Management)

| 编号    | 需求描述                                    | 优先级 |
|--------|-------------------------------------------|--------|
| FR-B-01 | 管理员可新增图书（书名、作者、ISBN、出版社、分类、总册数） | P0 |
| FR-B-02 | 管理员可修改图书信息                           | P0 |
| FR-B-03 | 管理员可删除图书（仅当无未归还借阅记录时）          | P1 |
| FR-B-04 | 管理员可按书名/作者/ISBN/分类查询图书             | P0 |
| FR-B-05 | 系统展示每本图书的可借数量（总册数 - 已借出）        | P0 |
| FR-B-06 | 图书状态自动更新（可借/已借完/维护中）             | P0 |

### 2.2 用户管理模块 (User Management)

| 编号    | 需求描述                                    | 优先级 |
|--------|-------------------------------------------|--------|
| FR-U-01 | 管理员可注册新用户（姓名、手机、邮箱、地址、会员类型）   | P0 |
| FR-U-02 | 管理员可修改用户信息                           | P1 |
| FR-U-03 | 管理员可按姓名/手机号查询用户                    | P0 |
| FR-U-04 | 不同会员类型有不同借阅上限和借阅期限               | P0 |

**会员类型规则：**

| 会员类型 | 最大借阅数 | 借阅期限 |
|---------|-----------|---------|
| 学生    | 5 本      | 15 天   |
| 教师    | 10 本     | 30 天   |
| 公众    | 3 本      | 14 天   |

### 2.3 借阅管理模块 (Borrow Management)

| 编号    | 需求描述                                    | 优先级 |
|--------|-------------------------------------------|--------|
| FR-L-01 | 用户可借阅图书（系统校验可借数量及库存）            | P0 |
| FR-L-02 | 用户可归还图书（更新库存及记录状态）               | P0 |
| FR-L-03 | 系统自动计算应还日期（根据会员类型）               | P0 |
| FR-L-04 | 同一用户不能重复借阅同一本书（未归还时）            | P1 |
| FR-L-05 | 系统可查询用户的当前借阅和历史借阅记录              | P0 |
| FR-L-06 | 系统可查询某本图书的借阅历史                     | P1 |
| FR-L-07 | 超期未还标记和提醒                             | P2 |

---

## 3. 非功能性需求 (Non-Functional Requirements)

| 编号     | 类别       | 需求描述                                         |
|---------|-----------|------------------------------------------------|
| NFR-01  | 性能      | 查询接口响应时间 < 500ms（常规负载）                   |
| NFR-02  | 可用性    | 系统可用性 >= 99%（非 7x24 核心系统）                  |
| NFR-03  | 安全性    | API 需做基本的参数校验，防止 SQL 注入（ORM 层防护）       |
| NFR-04  | 可维护性  | 代码遵循分层架构，注释覆盖率 >= 30%                     |
| NFR-05  | 数据一致性 | 借还操作需保证事务一致性                               |
| NFR-06  | 扩展性    | 模块间低耦合，后续可拆分微服务                           |

## 4. 用例分析 (Use Cases)

### 4.1 系统角色

- **管理员 (Admin/Librarian)**：拥有系统全部操作权限
- **借阅用户 (Borrower)**：仅可查询和借还（本次迭代简化，所有 API 面向管理员）

### 4.2 用例图描述

```
+---------------------------------------------------+
|                   图书管理系统                       |
|                                                   |
|   管理员 ──── 新增图书                               |
|   管理员 ──── 修改图书                               |
|   管理员 ──── 删除图书                               |
|   管理员 ──── 查询图书                               |
|   管理员 ──── 注册用户                               |
|   管理员 ──── 查询用户                               |
|   管理员 ──── 办理借书                               |
|   管理员 ──── 办理还书                               |
|   管理员 ──── 查询借阅记录                            |
+---------------------------------------------------+
```

### 4.3 核心用例描述

**用例 UC-01：借阅图书**

| 项       | 描述                                          |
|---------|---------------------------------------------|
| 参与者   | 管理员                                        |
| 前置条件 | 用户已注册，图书有库存                            |
| 主流程   | 1. 管理员输入用户ID和图书ID                       |
|         | 2. 系统校验用户借阅数量未达上限                     |
|         | 3. 系统校验图书可借数量 > 0                        |
|         | 4. 系统创建借阅记录，更新图书库存                   |
|         | 5. 系统返回借阅成功信息                           |
| 异常流程 | 2a. 用户借阅已达上限，提示"借阅数量已达上限"           |
|         | 3a. 图书库存不足，提示"该图书已全部借出"              |
|         | 4a. 同一本书重复借阅，提示"您已借阅此书，请勿重复借阅"   |
| 后置条件 | 借阅记录创建成功，图书可借数量-1                      |

**用例 UC-02：归还图书**

| 项       | 描述                                          |
|---------|---------------------------------------------|
| 参与者   | 管理员                                        |
| 前置条件 | 存在对应的借阅记录且状态为"借阅中"                   |
| 主流程   | 1. 管理员输入借阅记录ID                           |
|         | 2. 系统将借阅记录状态改为"已归还"                   |
|         | 3. 系统将归还日期设为当前日期                      |
|         | 4. 系统增加图书可借数量                           |
|         | 5. 系统判断是否超期并标记                          |
| 异常流程 | 1a. 记录不存在，提示"借阅记录不存在"                  |
|         | 1b. 记录已归还，提示"该记录已归还"                   |
| 后置条件 | 借阅记录状态更新，图书可借数量+1                      |

## 6. 约束与假设

### 6.1 约束
- 系统为单机部署，不考虑分布式场景
- 数据库使用 MySQL 8.0+
- API 暂不做认证鉴权（预留扩展点）

### 6.2 假设
- 每本书的复本（多册）用 `totalCopies` 和 `availableCopies` 表示，不区分具体册号
- 用户由管理员统一管理注册，无自助注册
- 续借功能纳入后续迭代
