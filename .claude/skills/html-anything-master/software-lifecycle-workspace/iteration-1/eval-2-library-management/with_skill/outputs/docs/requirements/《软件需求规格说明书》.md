# 软件需求规格说明书 (SRS)

## 1. 引言

### 1.1 编写目的

本文档旨在明确图书管理系统（LMS）的功能需求和非功能需求，作为后续设计、开发和测试的依据。本文档的目标读者包括系统架构师、开发工程师、测试工程师和项目管理人员。

### 1.2 项目范围

本系统是一个简易的图书管理系统，服务于图书馆的日常借还书业务。系统覆盖图书管理、读者管理、借阅管理三大核心模块，提供 RESTful API 供前端或第三方系统调用。

不包含的功能（本期不做）：
- 图书预约功能
- 图书续借功能
- 罚金管理
- 图书推荐
- 数据统计报表
- 读者自助终端
- 邮件/短信通知

## 2. 系统概述

### 2.1 系统总体描述

图书管理系统是一个基于 B/S 架构的后端服务系统，通过 RESTful API 提供图书管理、读者管理和借阅管理功能。图书管理员通过前端界面（不在本项目范围内）调用 API 完成日常操作，系统负责数据持久化、业务逻辑处理和状态管理。

### 2.2 用户角色定义

| 角色 | 描述 | 权限范围 |
|------|------|----------|
| 图书管理员（Librarian） | 图书馆工作人员，负责图书和读者管理、处理借还书业务 | 全部功能 |
| 系统管理员（Admin） | 负责系统配置和维护（本期仅预留角色，不实现具体功能） | 系统配置 |

说明：本系统为简化版本，不实现读者自助操作功能，所有操作由图书管理员代为执行。

### 2.3 运行环境

| 项目 | 要求 |
|------|------|
| JDK | JDK 17 或以上 |
| 数据库 | MySQL 8.0 |
| 操作系统 | Linux / Windows / macOS |
| 内存 | 至少 512 MB |
| 磁盘 | 至少 1 GB 可用空间 |

## 3. 功能需求

### 3.1 图书管理

#### 3.1.1 新增图书 (FR-BOOK-001)

- **描述**: 图书管理员录入新书信息到系统中
- **输入**:
  - ISBN（必填，唯一）
  - 书名（必填）
  - 作者（必填）
  - 出版社（可选）
  - 出版年份（可选）
  - 图书分类（可选）
  - 馆藏数量（必填，正整数）
  - 图书位置/书架号（可选）
- **输出**: 新创建的图书信息（含系统生成的图书 ID）
- **前置条件**: 管理员已登录，ISBN 在系统中不存在
- **后置条件**: 图书信息被持久化到数据库，可借数量等于馆藏数量
- **优先级**: Must

#### 3.1.2 查询图书 (FR-BOOK-002)

- **描述**: 图书管理员根据条件查询图书信息
- **输入**: 可选查询条件 — ISBN、书名关键词、作者、分类
- **输出**: 符合条件的图书列表（分页）
- **前置条件**: 无
- **后置条件**: 无
- **优先级**: Must

#### 3.1.3 查询单本图书详情 (FR-BOOK-003)

- **描述**: 通过图书 ID 查询单本图书的详细信息及在馆状态
- **输入**: 图书 ID
- **输出**: 图书详细信息（含当前可借数量、总馆藏数量）
- **前置条件**: 图书存在于系统中
- **后置条件**: 无
- **优先级**: Must

#### 3.1.4 修改图书信息 (FR-BOOK-004)

- **描述**: 图书管理员修改已有图书的基本信息
- **输入**: 图书 ID + 要修改的字段
- **输出**: 修改后的图书信息
- **前置条件**: 图书存在于系统中
- **后置条件**: 图书信息更新
- **优先级**: Should

#### 3.1.5 删除图书 (FR-BOOK-005)

- **描述**: 图书管理员删除系统中已无馆藏的图书记录
- **输入**: 图书 ID
- **输出**: 操作结果
- **前置条件**: 该图书当前无外借记录（所有书已归还）
- **后置条件**: 图书记录被删除
- **优先级**: Should

### 3.2 读者管理

#### 3.2.1 新增读者 (FR-READER-001)

- **描述**: 图书管理员为读者注册借阅账户
- **输入**:
  - 姓名（必填）
  - 联系电话（必填）
  - 邮箱（可选）
  - 读者类型（必填，如：学生/教师/普通）
- **输出**: 新创建的读者信息（含系统生成的读者 ID）
- **前置条件**: 管理员已登录
- **后置条件**: 读者信息被持久化
- **优先级**: Must

#### 3.2.2 查询读者 (FR-READER-002)

- **描述**: 图书管理员查询读者信息
- **输入**: 读者 ID 或姓名关键词
- **输出**: 符合条件的读者列表（分页）
- **前置条件**: 无
- **后置条件**: 无
- **优先级**: Must

#### 3.2.3 修改读者信息 (FR-READER-003)

- **描述**: 图书管理员修改读者信息
- **输入**: 读者 ID + 要修改的字段
- **输出**: 修改后的读者信息
- **前置条件**: 读者存在于系统中
- **后置条件**: 读者信息更新
- **优先级**: Should

#### 3.2.4 删除读者 (FR-READER-004)

- **描述**: 图书管理员删除读者账户
- **输入**: 读者 ID
- **输出**: 操作结果
- **前置条件**: 该读者当前无未归还的借阅记录
- **后置条件**: 读者信息被删除
- **优先级**: Should

### 3.3 借阅管理

#### 3.3.1 借书 (FR-BORROW-001)

- **描述**: 图书管理员为读者办理借书手续
- **输入**:
  - 图书 ID（必填）
  - 读者 ID（必填）
  - 借阅天数（可选，默认 30 天）
- **输出**: 借阅记录（含借阅日期、应还日期）
- **前置条件**:
  1. 图书存在且可借数量 > 0
  2. 读者存在且账户状态正常
  3. 该读者未借过同一本书（不允许重复借阅）
- **后置条件**:
  1. 图书可借数量减 1
  2. 生成一条借阅记录，状态为"借出"
- **优先级**: Must

#### 3.3.2 还书 (FR-BORROW-002)

- **描述**: 图书管理员为读者办理还书手续
- **输入**: 借阅记录 ID
- **输出**: 更新后的借阅记录（含实际归还日期）
- **前置条件**:
  1. 借阅记录存在且状态为"借出"
- **后置条件**:
  1. 借阅记录状态更新为"已归还"
  2. 实际归还日期记录为当前日期
  3. 图书可借数量加 1
- **优先级**: Must

#### 3.3.3 查询借阅记录 (FR-BORROW-003)

- **描述**: 按条件查询借阅历史记录
- **输入**: 可选条件 — 读者 ID、图书 ID、借阅状态（借出/已归还）、借阅日期范围
- **输出**: 符合条件的借阅记录列表（分页）
- **前置条件**: 无
- **后置条件**: 无
- **优先级**: Must

#### 3.3.4 查询逾期借阅 (FR-BORROW-004)

- **描述**: 查询所有逾期的借阅记录（应还日期已过但未归还）
- **输入**: 无（或可选日期截止参数）
- **输出**: 逾期借阅记录列表
- **前置条件**: 无
- **后置条件**: 无
- **优先级**: Should

## 4. 非功能需求

### 4.1 性能需求

| 指标 | 要求 |
|------|------|
| API 响应时间 | 单次 CRUD 操作 < 500ms（P95） |
| 并发支持 | 至少支持 20 个并发请求 |
| 数据量 | 支持万册级别的图书管理 |

### 4.2 安全需求

- API 调用需进行基本的身份认证（本期简化实现，通过固定 Token 校验）
- SQL 注入防护：使用参数化查询（Spring Data JPA 默认提供）
- 敏感数据（如读者电话）在日志输出中脱敏处理

### 4.3 可用性需求

- API 响应格式统一为 JSON：`{"code": 0, "message": "success", "data": ...}`
- 业务异常返回明确的中文错误提示
- 系统可用性目标：99%（非 7x24 运行场景）

### 4.4 可维护性需求

- 代码分层清晰：Controller -> Service -> Repository
- 关键业务逻辑有单元测试覆盖（目标覆盖率 80%+）
- API 接口遵循 RESTful 规范

### 4.5 兼容性需求

- 数据库兼容 MySQL 8.0+
- JDK 兼容 17+

## 5. 数据需求

### 5.1 数据实体概述

| 实体 | 描述 | 关键属性 |
|------|------|----------|
| Book（图书） | 馆藏图书信息 | ISBN, 书名, 作者, 馆藏数量, 可借数量 |
| Reader（读者） | 读者信息 | 姓名, 联系电话, 读者类型 |
| BorrowRecord（借阅记录） | 每次借阅的记录 | 图书 ID, 读者 ID, 借阅日期, 应还日期, 实际归还日期, 状态 |

### 5.2 数据约束

- ISBN 全局唯一
- 读者联系电话唯一（同一号码不能注册多个读者）
- 可借数量 <= 馆藏数量
- 每个读者对同一本书同时只能有一条"借出"状态的记录
- 借阅记录的应还日期必须晚于借阅日期

## 6. 系统接口需求

### 6.1 用户界面需求

本期不实现图形用户界面，仅提供 RESTful API。API 接口遵循以下规范：

- URL 前缀: `/api/v1`
- 请求/响应格式: JSON
- 分页参数: `page`（页码，从 0 开始）, `size`（每页条数，默认 20）

### 6.2 外部接口需求

本期无外部系统集成需求。

## 7. 附录

### 7.1 用例图（文字描述）

```
图书管理员 ──┬── 图书管理（增删改查）
            ├── 读者管理（增删改查）
            └── 借阅管理（借书、还书、查询记录、逾期查询）
```

### 7.2 业务流程图

**借书流程**:
```
管理员选择读者 -> 选择要借的图书 -> 系统校验(读者有效/图书可借/无重复借阅) -> 生成借阅记录 -> 更新图书可借数量
```

**还书流程**:
```
管理员查找借阅记录 -> 确认还书 -> 系统校验(记录状态为"借出") -> 更新借阅记录(状态/归还日期) -> 恢复图书可借数量
```

### 7.3 术语表

| 术语 | 定义 |
|------|------|
| 可借数量 | 当前可被借出的图书册数 = 馆藏数量 - 当前借出数量 |
| 借阅状态 | 借出（BORROWED）/ 已归还（RETURNED） |
| 逾期 | 借阅记录的应还日期已过且状态仍为"借出" |
