# 软件需求规格说明书 (SRS)

## 1. 引言

### 1.1 编写目的

本文档旨在明确"批量文件重命名命令行工具"的功能需求、非功能需求和接口需求，为后续的概要设计、详细设计和编码实现提供依据。

### 1.2 项目范围

本工具是一个 Python 实现的命令行程序，允许用户使用正则表达式对文件进行批量查找和替换重命名。支持单目录和递归子目录处理、dry-run 预览模式、文件名过滤、冲突检测等特性。

**不包含**的功能：文件内容搜索与替换、GUI 界面、跨设备/远程文件操作。

## 2. 系统概述

### 2.1 系统总体描述

本系统是一个命令行工具，接收用户提供的正则表达式模式和替换字符串，扫描指定目录中的文件，对匹配模式的文件名执行正则替换，完成批量重命名。工具强调安全性和可预览性，提供 dry-run 模式供用户在正式执行前审查变更。

数据流：用户输入 -> CLI 参数解析 -> 文件扫描 -> 文件名匹配 -> 重命名映射生成 -> (dry-run 输出 / 实际执行) -> 结果报告

### 2.2 用户角色定义

| 角色 | 描述 |
|------|------|
| 普通用户 | 使用命令行工具进行批量重命名操作的开发者或系统管理员，需理解基本的正则表达式语法 |

### 2.3 运行环境

- **操作系统**：Linux、macOS、Windows 10+
- **Python 版本**：Python 3.8 及以上
- **磁盘空间**：< 1 MB（工具本身）
- **内存要求**：< 50 MB（典型使用场景）
- **网络要求**：无需网络连接

## 3. 功能需求

### 3.1 FR-1：基本重命名功能

#### 3.1.1 描述
用户提供一个正则表达式模式和一个替换字符串，工具在指定目录中匹配文件名，并执行替换。

#### 3.1.2 输入/输出
- **输入**：
  - `--pattern` / `-p`：正则表达式模式（字符串）
  - `--replacement` / `-r`：替换字符串，支持 `\1`、`\2` 等反向引用
  - `--directory` / `-d`：目标目录路径（必选，默认当前目录）
- **输出**：重命名操作执行结果报告（成功、跳过、失败的文件计数）

#### 3.1.3 前置条件与后置条件
- **前置条件**：目标目录存在且用户具有读写权限
- **后置条件**：匹配成功的文件名被重命名为替换后的名称；如有冲突则中止并报告

#### 3.1.4 优先级
**Must have**

---

### 3.2 FR-2：Dry-Run 预览模式

#### 3.2.1 描述
用户使用 `--dry-run` 标志，工具仅显示将要进行的重命名操作而不实际执行。

#### 3.2.2 输入/输出
- **输入**：`--dry-run` 标志（布尔型，默认 false）
- **输出**：列出每个文件的原名称和将要变成的新名称，以表格形式展示

#### 3.2.3 前置条件与后置条件
- **前置条件**：同 FR-1
- **后置条件**：文件系统不发生任何更改

#### 3.2.4 优先级
**Must have**

---

### 3.3 FR-3：递归子目录处理

#### 3.3.1 描述
用户使用 `--recursive` / `-R` 标志，工具递归处理目标目录及其所有子目录中的文件。

#### 3.3.2 输入/输出
- **输入**：`--recursive` / `-R` 标志（布尔型，默认 false）
- **输出**：递归遍历所有文件的结果报告

#### 3.3.3 前置条件与后置条件
- **前置条件**：用户对子目录具有读取和遍历权限
- **后置条件**：所有层级的匹配文件被重命名

#### 3.3.4 优先级
**Should have**

---

### 3.4 FR-4：文件名过滤

#### 3.4.1 描述
用户可指定文件名过滤条件（通配符或正则），仅处理符合条件的文件。

#### 3.4.2 输入/输出
- **输入**：`--filter` / `-f`：文件名过滤模式（glob 格式，如 `*.txt`），可选
- **输出**：仅对过滤后的文件执行重命名

#### 3.4.3 前置条件与后置条件
- **前置条件**：无
- **后置条件**：仅过滤条件匹配的文件被处理

#### 3.4.4 优先级
**Could have**

---

### 3.5 FR-5：文件名冲突检测

#### 3.5.1 描述
执行重命名前检测是否存在文件名冲突（两个不同文件被重命名为同一名称）。若检测到冲突，提示用户并中止操作。

#### 3.5.2 输入/输出
- **输入**：无额外输入（自动检测）
- **输出**：冲突文件列表和错误提示

#### 3.5.3 前置条件与后置条件
- **前置条件**：无
- **后置条件**：如发现冲突，文件系统不发生更改

#### 3.5.4 优先级
**Must have**

---

### 3.6 FR-6：大小写敏感控制

#### 3.6.1 描述
用户可控制正则匹配是否区分大小写。

#### 3.6.2 输入/输出
- **输入**：`--ignore-case` / `-i` 标志（布尔型，默认 false 即大小写敏感）
- **输出**：正则匹配行为相应调整

#### 3.6.3 前置条件与后置条件
- **前置条件**：无
- **后置条件**：无

#### 3.6.4 优先级
**Should have**

---

### 3.7 FR-7：详细输出模式

#### 3.7.1 描述
用户使用 `--verbose` / `-v` 标志，工具输出每个文件处理的详细信息。

#### 3.7.2 输入/输出
- **输入**：`--verbose` / `-v` 标志（布尔型，默认 false）
- **输出**：每个文件的处理状态和耗时

#### 3.7.3 前置条件与后置条件
- **前置条件**：无
- **后置条件**：终端输出更多信息

#### 3.7.4 优先级
**Should have**

---

### 3.8 FR-8：强制覆盖模式

#### 3.8.1 描述
用户使用 `--force` 标志，在目标文件已存在时允许覆盖（而非中止）。

#### 3.8.2 输入/输出
- **输入**：`--force` 标志（布尔型，默认 false）
- **输出**：覆盖警告

#### 3.8.3 前置条件与后置条件
- **前置条件**：用户明确知晓覆盖风险
- **后置条件**：同名目标文件被覆盖

#### 3.8.4 优先级
**Could have**

## 4. 非功能需求

### 4.1 性能需求

| 指标 | 目标值 |
|------|--------|
| 单目录处理速度 | 1000 个文件 < 1 秒 |
| 递归处理速度 | 10000 个文件 < 5 秒 |
| 启动时间 | < 200 毫秒 |
| 内存占用 | < 100 MB |

### 4.2 安全需求

- 不得删除或覆盖用户文件除非明确指定 `--force`
- 所有文件操作应使用原子性操作或具备回滚能力
- 输入的正则表达式应验证有效性，无效时给出明确错误提示

### 4.3 可用性需求

- `--help` 输出完整、清晰的使用说明和示例
- 错误信息应明确指出问题原因和建议的解决方案
- dry-run 模式默认建议用户先行预览

### 4.4 可维护性需求

- 代码结构模块化，核心逻辑与 CLI 接口分离
- 函数和类使用类型提示（Type Hints）
- 关键函数撰写 docstring

### 4.5 兼容性需求

- 支持 Python 3.8 至 3.12+
- 兼容 Windows、macOS、Linux 文件系统
- 正确处理 Unicode 文件名

## 5. 数据需求

### 5.1 数据实体概述

本工具不涉及持久化数据存储。运行时仅处理内存中的文件名映射数据结构：

- **RenameMapping**：包含 `original_path`（Path 对象）、`new_name`（字符串）、`status`（枚举：pending/success/skipped/failed）

### 5.2 数据约束

- 文件名长度不超过操作系统限制（通常 255 字节或字符）
- 正则替换后的文件名不得包含路径分隔符（`/` 或 `\`）

## 6. 系统接口需求

### 6.1 用户界面需求

命令行接口设计，使用 `argparse` 实现。基本用法示例：

```bash
# 基本用法：将 .txt 改为 .md
rename-tool -d ./docs -p '\.txt$' -r '.md'

# 预览模式
rename-tool -d ./photos -p 'IMG_(\d+)' -r 'Photo_\1' --dry-run

# 递归 + 忽略大小写
rename-tool -d ./project -p 'old_name' -r 'new_name' -R -i
```

### 6.2 外部接口需求

本工具为纯本地工具，无外部 API 或网络接口。

### 7.2 术语表

| 术语 | 定义 |
|------|------|
| Dry-run | 预览模式，展示操作计划但不执行 |
| 反向引用 | 正则替换中的 `\1`、`\2` 等，引用捕获组内容 |
| Glob | 文件名通配符模式，如 `*.txt` |
| 原子操作 | 不可分割的操作，要么完全成功，要么完全失败 |
